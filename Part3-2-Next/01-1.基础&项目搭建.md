## 1、Next.js 是什么

### 1-1. 核心价值主要体现

* 开箱即用：内置路由、SSR/SSG 渲染机制、数据获取模型和 React Server Components (RSC, React 服务器组件)。
* 性能与SEO：提供优秀的性能和 SEO 支持，平衡了性能与开发效率。
* 全栈开发：支持前端组件开发和后端 API 服务编写。
* 开发者体验：提供快速热更新（Fast Refresh）和通过 Vercel 实现的一键式部署（Zero-config Deployment）。

### 1-2. Next.js 三种主要渲染机制

* SSR（Server-Side Rendering, 服务器端渲染），在每次请求页面的时候，在服务器端去生成 HTML，适合动态、个性化页面。
* SSG（Static Site Generation, 静态站点生成） 它在系统本地构建时生成静态 HTML，适合内容稳定、SEO 友好页面。
* ISR（Incremental Static Regeneration, 增量静态再生成）：在静态与动态之间做平衡，按失效策略后台再生成。

 Next.js 脚手架初始化的目录结构：

```
next-demo/
├── app/                        # Next.js 应用核心目录
│   ├── favicon.ico             # 浏览器标签页图标
│   ├── globals.css             # 全局 CSS 样式文件，结合 Tailwind CSS 使用
│   ├── layout.tsx              # 根布局组件，包裹所有页面，管理字体、元数据等
│   └── page.tsx                # 应用主页面（默认首页）
├── public/                     # 静态资源目录
│   ├── file.svg
│   ├── globe.svg
│   ├── next.svg
│   ├── vercel.svg
│   └── window.svg
├── .gitignore                  # Git 忽略配置
├── eslint.config.mjs           # ESLint 配置文件
├── next-env.d.ts               # Next.js 类型声明文件
├── next.config.ts              # Next.js 全局配置文件
├── package.json                # 项目依赖与脚本
├── postcss.config.mjs          # PostCSS 配置文件
├── README.md                   # 项目说明
└── tsconfig.json               # TypeScript 编译配置
```

### 3、Next.js 与 TypeScript 的深度集成


**tsconfig.json 关键配置项：**

```jsonc
{
  "compilerOptions": {
    // 编译目标：输出 ES2017 语法，兼容大多数现代浏览器和 Node.js 环境
    "target": "ES2017",

    // 运行时类型库：DOM API + ES 最新特性
    "lib": ["dom", "dom.iterable", "esnext"],

    // 允许在 TS 项目中导入 .js 文件
    "allowJs": true,

    // 跳过 node_modules 中依赖库的类型检查，加快构建速度
    // 权衡：可能隐藏第三方库内部的类型问题
    "skipLibCheck": true,

    // 开启最严格的类型检查（包含 strictNullChecks、noImplicitAny 等），减少运行时错误
    "strict": true,

    // 仅做类型检查，不输出编译后的 JS 文件，实际构建交由 Next.js（Turbopack/SWC）处理
    "noEmit": true,

    // 允许 ES Module 和 CommonJS 模块之间的互操作
    // 例如：import React from 'react' 而不是 import * as React from 'react'
    "esModuleInterop": true,

    // 模块系统：使用 ESNext 模块语法（import/export）
    "module": "esnext",

    // 模块解析策略：使用 "bundler" 模式（TS5 推荐）
    // 配合现代打包器（Turbopack/Webpack）解析 ESM 导入，Next.js 项目推荐此选项
    "moduleResolution": "bundler",

    // 允许导入 JSON 文件，常用于读取配置文件
    // 例如：import config from './config.json'
    "resolveJsonModule": true,

    // 确保每个文件都可以被独立编译（不依赖其他文件的类型推断）
    // 这是 Next.js 和 SWC/Turbopack 正常工作的必要条件
    "isolatedModules": true,

    // JSX 转换模式：使用 React 17+ 的新版 JSX 转换
    // 不需要在每个文件顶部写 import React from 'react'
    "jsx": "react-jsx",

    // 增量编译：缓存上次编译结果，加快后续类型检查速度
    "incremental": true,

    // Next.js 专用插件，提供路由类型安全等增强功能
    "plugins": [
      {
        "name": "next"
      }
    ],

    // 路径别名：@ 映射到项目根目录
    // 例如：import Heading from '@/components/Heading' 等价于 './components/Heading'
    "paths": {
      "@/*": ["./*"]
    }
  },

  // 包含的文件范围
  "include": [
    "next-env.d.ts",          // Next.js 类型声明
    "**/*.ts",                 // 所有 .ts 文件
    "**/*.tsx",                // 所有 .tsx 文件
    ".next/types/**/*.ts",     // Next.js 构建生成的类型
    ".next/dev/types/**/*.ts", // Next.js 开发模式生成的类型
    "**/*.mts"                 // ES Module 格式的 .mts 文件
  ],

  // 排除 node_modules 目录
  "exclude": ["node_modules"]
}
```
